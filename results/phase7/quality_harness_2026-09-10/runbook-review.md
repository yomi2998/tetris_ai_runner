### Findings

- **P2, criterion must name the exact z.** Section 5 says "Wilson one-sided 95 percent lower bound" but the existing tuner code (`tuner.cpp` run_vs) computes the two-sided 95% interval with z=1.96. One-sided 95% requires z=1.6449; reusing 1.96 silently produces a stricter one-sided-97.5% bound, an undeclared criterion change. Fix before freeze: state "z = 1.6449, one-sided 95%" explicitly (or pre-declare the stricter two-sided variant knowingly). Smallest fix: one sentence in section 5.
- **P3, budget-scope symmetry should be verified, not assumed.** Value 20 ms maps to `SearchBudget::by_time` on the root search with setup and path outside (`profile_value_runner.h:287`, `:317`); legacy 20 ms bounds `run_hold` similarly. Pre-declare that both seats bound the search/root-search call, and require the smoke CSV to record per-seat per-move wall distributions so a systematic scope skew (>10%) is detected before the screen.
- **P3, thread oversubscription.** 8 concurrent pairs × 2 threads = 16 threads on 15 usable CPUs (CPU 15 offline). Symmetric within a pair and averaged over 2000 games, but consider 7 concurrent pairs or record the oversubscription explicitly in `MACHINE.md`.
- **P3, arena-exhaustion scoring.** At 20 ms budgets arena exhaustion is implausible, but specify the recorded behavior if `exhausted_` fires mid-game (count it as a seat death with the counter reported, never silent).
- **P3, "no production source changes" precision.** Adding `engine1`/`engine2` to `MatchJob` modifies the shared tool header `src/tuner_match.h`. Require default engine ids = legacy on both fields and a post-change rerun of `migration_compare` determinism (zero mismatches) to prove the existing tools are behavior-identical.
