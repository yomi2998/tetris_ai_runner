## Findings

- **P2, binding rows report last-input work counters, not totals.** `legacy_fast_adapter_bench.cpp` resets `counts = legacy_diag::Counts{}` per replay input, but the `DIAG_V1` row prints `counts.searches` and `counts.candidates`, which therefore hold only the final input's values, while `path_ok`/`path_fail`/`dead` are cumulative. Section 8.4's candidate-count identity evidence and the L0/L1 work-partition deliverable need cumulative volumes. Fix: accumulate `total_searches`/`total_candidates` and print those. Must land before Step 1/Step 3 collection because it changes binary hashes.
- **P2, silent arrival relabel in `make_path`.** `AdapterSearch::make_path` (`legacy_host_diag_common.h:367-371`) falls back from `TerminalRotation` to `Normal` when the rotation-final path is invalid, with no counter. Runbook gate 3 requires path/replay failures to be hard stops or counted categories; an uncounted relabel can present a T-spin-classified landing whose executed path is not rotation-final. Fix: add a dedicated `path_relabels` counter, require zero during feasibility, and treat repeats as a gate-3 failure.
- **P2, the EvalAudit hook is untested.** The 247-check suite covers enumeration parity, determinism, conversion, and domain flags, but no test sets `audit_enabled()`/`exact_only()` and drives `TetrisCore::eval` to verify epoch reset, collision counting, exact-hit semantics, or L2 retargeting. The worker's summary claimed audit tests; they are not in the file. Fix: add directed tests (a minimal legacy-engine run with a forced collision, plus an `exact_only` retarget check) before Step 3, since the audit sits in the timed path of the binding comparison.
- **P3, runbook 6.3 sink-equality clause not literally implemented.** The S1 sink is checked nonzero and the poisoned-board check exists, but there is no untimed-digest-equals-timed-sink assertion; per-drive case rotation makes hoisting structurally impossible, so acceptable with disclosure in `step1/MACHINE.md`.
- **P3, board-class distribution under-delivered.** `digest_cases` counts `t_terminal` but `(void)`s `unmappable`/`spawn_blocked`, and per-class medians (classes a-e) are not reported; output is per-piece only. Report class counts in `step1/summary.json` during finalization or accept the reduction explicitly.
- **P3, collector budget and shape deviations.** Three prewarm runs versus the budgeted four (the L1 selfplay path gets no discarded prewarm); 36 total commands versus 37; no per-round recheck wait (aborts on load5 >= 2.0 instead of waiting; stricter but abort-prone); binding-row check is `grep -q '^DIAG_V1 '` without a single-line assertion; anchor runs get no stderr/row-shape check; `digests.sha256` actually contains row and prewarm hashes, and no `rows.sha256` or candidate-digest file is written. Fix naming and the single-line check during finalization or before execution.
- **P3, audit-overhead asymmetry disclosure.** The audit is common-mode across L0/L1/L2 (memcmp per eval request), but its fresh-recompute branch fires only on legacy-table collisions, whose rate differs per arm's eval stream; V carries none. Collision counts are printed per row, but `step4/REPORT.md` must state this asymmetry when reading E1/E3.
- **P3, L2 aliasing is reduced, not eliminated.** The audit slot mixes depth into a single 2^17-entry table, so cross-depth and residual same-slot overwrites can still mutate `&entry.value` between eval and consumption; per-depth aliasing is strictly rarer than the legacy 2^16 per-depth tables. Disclose in the E2 analysis; do not describe L2 as perfectly alias-free.
