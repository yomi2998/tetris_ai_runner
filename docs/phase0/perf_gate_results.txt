Two earlier records were withdrawn. The 2026-09-03 run used a comparator that was
a locally written program driven by this repository's own oracle instead of
Reference A, and published hashes for only the first corpus board. The
2026-09-04T13:20 run compared the right implementations but its raw harness
shifted its sink by `rep % 32` while `rep` was still negative during warmup
repetitions, which is undefined behavior; UBSan stops it with
"shift exponent -1 is negative". The harness now shifts by an unsigned index, and
two new CTest warmup smoke runs execute it with `--warmup 3` inside a sanitizer
build so the class of defect cannot return silently. Conclusions did not change:
this corrected campaign clears both gates with more margin, and every recorded

## Candidate contract

`src/candidate_format.h` normalizes both sides to physical placements:

- A key is the FNV-1a hash of the four occupied cells sorted by index, computed
  from each side's own geometry table, so duplicate I, S, and Z orientation
  representations collapse into one candidate.
- Arrival history is dropped for every non-T piece.
- T keeps at most two candidates per physical placement: normal and terminal
  rotation.
- All 7 pieces times 37 corpus boards are reported, each case with a count, a set
  hash, and a corpus hash over the ordered table. Empty-board normalized counts
  are T 60, Z 17, S 17, J 34, L 34, O 9, I 17, on both sides.
- `--dump-keys` additionally emits every normalized key, which lets
  `tests/check_candidate_inclusion.py` compare actual sets rather than counts.

- `raw_parity_frozen_180off`: the same 259 rows identical against the plain
  frozen kernel with 180 disabled on both sides.
- `t_contract_reference_a_180off`: the 259 normalized T contract rows byte
  identical against the real Reference A wrapper with 180 off on both sides,
  corpus hash `27f4998e663f3604`.
- `t_contract_reference_a_production`: with 180 on, key-by-key set inclusion:
  all 4416 Reference A candidate keys appear inside this implementation's 4535,
  and the 119 extras are confined to J (102) and L (17). This compares dumped
  keys, not counts, so a different but larger set would fail. Reference A's
  frozen kernel ignores `allow_180` entirely, which this campaign confirms
  directly: its 180-on corpus hash equals its 180-off corpus hash, so it cannot
  emit a single 180 arrival. Every extra key is legal under the independent
  scalar command oracle, which this kernel matches exactly on 37 boards, 8
  movement configurations, and both `check_consecutive` modes.
- `raw_bench_warmup_smoke` and `raw_bench_warmup_smoke_frozen`: the raw harness
  runs `--reps 2 --warmup 3` and must exit cleanly; in the sanitizer build that
  is what catches invalid warmup handling.

## Timing method

The timed unit on both sides is one board: board preparation, enumeration, and
contract normalization. Shared normalization therefore dilutes the ratio toward
1, and the total rows are the conservative reading. The raw comparator also
measures a per-piece extraction calibration (the same result consumption with no
search), and the `search` rows subtract it; that reading amplifies differences
and also passes.

Each observation averages the internal repetitions of one process run (3000
iterations per board for the raw pair, 300 for the Reference A pair, after 10
warmup iterations). One protocol repetition runs the two sides in ABBA order and
averages the two same-side observations, giving five paired ratios per piece; the
gate statistic is the median of those pairwise ratios, never a ratio of aggregate
medians. A trailing extra run of side A follows the fifth repetition and is
retained in the raw rows as a drift control.

The machine runs the `powersave` governor with boost enabled and other processes
active, so absolute nanoseconds drift between campaigns; the frequency at the
start of this campaign is in the environment block, and the core pin plus ABBA
interleaving are what control for it.

## Sensitivity controls

Each of these was reproduced by re-introducing the defect in a scratch build and
then restoring the committed source, so the tests are known to be able to fail.

- Seeding every fitting spawn pose again: the spawn-fringe submodule cases fail
  with "alternate orientation is never a normal landing", and the root suite
  reports 12 oracle comparison failures over the 37-board corpus. The earlier
  27-board corpus reported none, which is why the fringe boards were added.
- Removing the `allow_180` propagation: the I orientation 2 rotation-landing and
  180 growth cases fail, and raw landing parity against the frozen kernel with
  the 180 fix breaks.
- Removing the range checks from `move_checker::is_valid`: the move checker suite
  fails 772 checks, including the pinned "row 47 upward kick cannot return anchor
  row 48" case.
- Shifting the raw bench sink by the signed repetition index again: UBSan stops
  the run with "shift exponent -1 is negative" during warmup and the
  `raw_bench_warmup_smoke` tests fail in the sanitizer build.
- Comparing only candidate counts in the production contract gate, as the
  previous revision did, cannot see a set that differs while being at least as
  large. That weakness was identified in review and replaced by the key-by-key
  checker, which now also treats a case whose dumped keys disagree with its
  reported count, or a case row present on only one side, as a failure.
- A clang build directory left half-updated by the ninja dependency scanning
  assertion made the inclusion checker report 290 missing keys, because the two
  stale binaries did not understand `--dump-keys` yet still printed identical
  case tables. That is a build staleness signal, not a semantic difference: the
  checker exits nonzero on it, and after rebuilding, Clang Debug and Clang
  self-release pass 9 of 9.
- With the committed sources, all 8 movement configurations match the scalar
  command oracle on all 37 boards in both `check_consecutive` modes.
