## Exact model

`tests/eval_index_screen_core.cpp` streams the accepted 5.16 GB trace and simulates live-node indexes without modifying production code or build files. It excludes warmup without priming state, scopes parents by reset epoch plus NodeId, bypasses exact parent-local memo hits, clears indexes on arena reset, repopulates from NodeLive records, and requires full 64-byte Board equality for every hit. Hashes and tags can only reject or select candidates; they cannot establish equality.

The screen covers raw FNV, splitmix-finalized FNV, and fmix-finalized existing occupancy fingerprints; 1/2/4/8-way LRU; 4-byte NodeId-only and 8-byte tag-plus-NodeId slots; and five capacities. LRU order bytes are included in memory totals. A 65,536-byte residual margin distinguishes practical eligibility from bare arithmetic fit.

Lookup probes, exact comparisons, LRU writes, insertions, and cache effects remain unmeasured.

## Verdict

- `PRIMARY_0.90=NO-ADVANCE`: the offline screen supplies no measured medians and cannot establish the 10 percent faster target.

This verdict blocks automatic production advance. It does not claim the index cannot achieve either target.
